## Definities (gelden voor elke rij en voor de evaluator)
```sh
# ref per rij: remote heeft voorrang, anders lokaal
r="origin/$b"; git rev-parse -q --verify "$r^{commit}" >/dev/null || r="$b"
achter_voor=$(git rev-list --left-right --count origin/main..."$r")         # "Achter Voor"
cherry=$(git cherry origin/main "$r" | grep -c '^+')                          # Cherry-uniek
mb=$(git merge-base origin/main "$r")                                         # leeg = geen gemeenschappelijke basis
tree=$(comm -12 <(git diff --name-only "$mb" "$r" | sort) \
                <(git diff --name-only origin/main "$r" | sort) | wc -l | tr -d ' ')   # Tree-uniek
```
- **Cherry-uniek** = aantal commits op de branch zonder patch-equivalent in `origin/main`. Vangt rebase/cherry-pick, maar **niet** squash-merges (één squash-commit matcht geen losse commits).
- **Tree-uniek** = aantal bestanden dat de branch sinds de merge-base wijzigde én dat in `origin/main` nog anders is. `0` betekent: alle inhoud van de branch staat al in `origin/main` (vangt squash-merges). Geen merge-base → in de kolom `geen-mb`, en de rij mag niet `delete` worden.
- Bij `Waar = beide` en verschillende sha's lokaal/remote: cijfers van de remote-ref in de kolom, en in de Reden `lokaal: cherry X, tree Y`.

## Risico en rollback
- Risico: `git cherry` op 100+ branches met grote blobs (41 MB `index.html`) is traag. Mitigatie: één lus, uitvoer naar een tijdelijk bestand buiten de repo (`/tmp/bl001b.tsv`), niet per rij opnieuw opbouwen.
- Risico: remote-tracking refs zijn verouderd omdat er niet gefetcht wordt. Mitigatie: kop vermeldt "op basis van lokale refs, laatste fetch onbekend"; Dennis kan vóór de opruiming fetchen en dit script herdraaien.
- Risico: `Tree-uniek = 0` terwijl de branch bestanden verwijderde die `main` nog heeft: die tellen juist als uniek (ze verschillen), dus geen vals `delete`.
- Risico: lokaal-only branches (`pr7`, `pr70`) zijn bij verwijdering onherstelbaar. Mitigatie: alleen `delete` als Cherry of Tree 0 is; anders blijft `archive` (tag eerst).
- Rollback: alleen documentwijzigingen; `git checkout -- ops/` of revert van de commit. Er worden geen refs aangeraakt.
