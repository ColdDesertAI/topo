# Sprintcontract — BL-007 Karakterisering terug op main en groen op V3 (M1 stap 1)

**Doel (1 zin):** de gedragstests uit de karakterisering staan op `main` en zijn groen op de live V3, zodat de runtime-migratie (M1) kan beginnen zonder gedrag te verliezen.
**Waarom nu:** M1 (deadline 11-12) begint met deze vangnetlaag (`docs/v3/ARCHITECTUUR.md` §2 stap 1). Raakt de site niet.
**Bouwer:** Claude Code (Sonnet, `builder`) · **Evaluator:** `evaluator` (Opus) · **Max runs:** 1/3

## Scope
- **Wel:** `tests/characterization/` overnemen uit tag `archive/t/BL-007-karakterisering` (`5fb379c`); aanpassen waar V3 bewust ander gedrag heeft (elke aanpassing met verwijzing naar het besluit in `docs/DECISIONS.md` of een BL-item); opnemen in `npm test`.
- **Niet:** app-code, `index.html`, `src/v2/`, `scripts/v3/` wijzigen. Geen nieuwe dependencies. Geen extractie (dat is stap 2).
- **Mag wijzigen:** `tests/characterization/**`, `package.json` (alleen het testscript), `ops/reports/BL-007.md` (nieuw).
- **Lezen:** `docs/v3/ARCHITECTUUR.md` §1–2, `tests/characterization/README.md` uit de tag, `docs/v3/SPEC.md`. `docs/DECISIONS.md` alleen gericht met `grep -n`.

## Bundels
1. Tests overnemen en draaien op `main`; rapport per test: groen / rood / bewust ander gedrag.
2. Rode tests oplossen: bij een bug in de test de test fixen; bij bewust V3-gedrag de verwachting aanpassen met bronverwijzing; bij een echte regressie **niets in de app fixen** maar een issue + BL-item aanmaken.
3. Opnemen in `npm test`, README bijwerken (wat elke test bewaakt, hoe draaien), rapport afronden.
