## Toelichting bij de drie aandachtspunten

1. **`npm run build:site` exit 1.** Bevestigd en al aanwezig op origin/main. Een volledige `git worktree add` lukte niet, want de schijf was vol (626 MB vrij, "No space left on device"). De mislukte worktree is met `git worktree prune` opgeruimd. In plaats daarvan heb ik `git archive origin/main portal scripts package.json` uitgepakt in `/tmp/bl041a-base`, met een symlink naar `assets` en een APFS-kloon van een verse `dist/` uit `npm run build`. Daar heb ik de build-site en verify-site van base gedraaid. Resultaat: exit 1 met dezelfde `AssertionError: /italie/ heeft niet dezelfde favicon-set als het portal`. `index.html`, `build.mjs`, `build-site.mjs` en `verify-site.mjs` zijn tussen base en head byte-gelijk (lege diff). De oorzaak: het standaardpad `SITE_ITALIE=v2` zet de V2-app met ingebedde data:-favicons op /italie/, terwijl de check uit BL-036.9 de portalset eist. Met de productievariabele `SITE_ITALIE=v3` is het exit 0. Dit komt dus niet door BL-041a.
2. **Overgeslagen Italië-assertie na een tik.** Dat is conform het contract. De kolom Verwacht zegt "op alle niet-actieve kaarten", en de toestand komt van `:focus-within` door de focus op de link in Chromium, niet van hover. Na blur is het neutraal, en in WebKit hangt ook Italië niet. Een kanttekening: het script slaat Italië onvoorwaardelijk over en controleert niet dat `activeElement` de link is. Een toekomstige echte hover-regressie op de Italië-kaart zou het daardoor in Chromium missen. Dit is geen FAIL, wel een verbeterpunt (zie hieronder).
3. **Playwright via NODE_PATH.** Werkt (1.58.2, browsers in `~/Library/Caches/ms-playwright`). De repo zelf heeft geen Playwright-dependency, dus de QA-scripts zijn niet zonder deze externe map te draaien.

## Buiten scope opgemerkt (→ backlog-idee)
- `npm run build:site` zonder `SITE_ITALIE=v3` faalt sinds BL-036.9 altijd (de favicon-assert past niet bij V2 op /italie/). Twee opties: de assert alleen voor V3 laten gelden, of de standaard op v3 zetten. Contracten zouden `SITE_ITALIE=v3 npm run build:site` moeten noemen, of `npm run build && …`, want zonder een verse `npm run build` faalt build:site al op "Draai eerst npm run build".
- `qa-portal-hover.mjs`: in plaats van Italië over te slaan, controleren dat `activeElement` de link is en na `blur()` alt 0 en transform none eisen. Ook WebKit draaien, waar een tik geen focus geeft.
- Playwright is geen devDependency van de repo. De QA-scripts hangen af van een `NODE_PATH` naar een ander project.
- De schijf van de Mac is vrijwel vol (626 MB vrij). Een volledige worktree lukt niet meer, en `output/html/` bevat meerdere kopieën van ~41 MB.
- Op de Voortgang-screenshot 1440×900 ligt de rijdende Vespa/Nino over de legenda "Nog niet" onderaan de kaart (bestaand, niet door deze taak).

## Les
Een acceptatiecriterium "`npm run build:site` exit 0" is niet toetsbaar zonder de variabele en de voorafgaande `npm run build`. Noem in het contract het exacte commando met omgeving (`npm run build && SITE_ITALIE=v3 npm run build:site`). Dan hoeft niemand een "al op main zo"-claim te verifiëren.
